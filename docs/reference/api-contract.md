## ABI 与所有权

- C ABI 只使用固定宽度整数、带长度的 UTF-8、opaque handle、结构大小/版本及预留字段；不跨边界暴露 C++
  容器、异常或平台对象。
- engine、subscription、task 引用、snapshot、event 和 lease 均明确释放入口。输入只在调用期间借用；异步需要的数据由
  SDK 复制。输出字符串归其所属 snapshot/event，不能超过对象生命周期使用。
- C++ 使用 RAII；Kotlin 使用类型化请求/快照/错误与可关闭租约。C/JNI 入口捕获内部异常并映射错误；Java
  异常检查和 native 失败均有明确结果。
- 不能在核心队列上同步执行磁盘、摘要、网络或用户回调。宿主回调经指定 executor 顺序分发，不持内部锁。
- M1 增加纯 C 编译/链接调用测试。完整 ABI、结构布局和实际导出清单在发布前验证；本文不是稳定二进制发布声明。

## 资源、任务与订阅

资源身份为 `(namespace, resource_key, version, representation_key)`；URL
和鉴权不构成身份。相同身份只有一个持久化任务和写入者，多个请求返回独立订阅。预期长度、可信摘要或
require_digest 冲突返回参数/约束错误，不覆盖已有任务。

| 能力                  | 固定语义                                                                                                             |
|-----------------------|----------------------------------------------------------------------------------------------------------------------|
| open                  | 获取受管目录单进程锁，扫描并修复记录。恢复任务默认不自动启动；同目录再次打开返回 Busy                                |
| enqueue               | 校验身份与约束，创建任务或复用相同身份任务，返回订阅与可查询 task 引用                                               |
| attach                | 宿主对持久化 task 重新建立内存订阅；不恢复旧回调和凭证                                                               |
| pause(task)           | 对共享任务整体生效，所有订阅都收到状态；task 控制权由宿主 API 持有者管理。Paused 才表示 I/O 停止且检查点成功         |
| resume(task)          | 对共享任务整体生效，需要有效订阅、宿主执行许可与可获取的请求信息；创建新 generation                                  |
| cancel(subscription)  | 撤销该订阅；其他订阅继续。最后一个订阅显式取消时取消共享任务并清理未完成数据；不删除已完成对象                       |
| release(subscription) | 解除回调。最后一个订阅释放时停止活动 I/O、尽力提交并保留可恢复的暂停任务；区别于显式取消                             |
| query/listTasks       | 返回不可变快照，包含 received/committed、总长是否已知、完整性结果和错误；列表使用分页                                |
| acquire               | 仅对记录和文件一致、未过期的 Completed 资源返回只读租约；不会暴露暂存路径                                            |
| pin/unpin             | 持久化业务保留标记，只影响 SDK 淘汰，不绕过过期/校验，不承诺系统永远不清理目录                                       |
| remove/trimTo         | 不能回收有租约的对象；trimTo 也不能回收 pin 对象。显式 remove(pin) 返回 Busy，先显式 unpin；活动资源删除须先停止任务 |

取消被撤销的订阅与共享任务的终态是两类事件，不能向仍在等待的订阅者错误广播 Cancelled。重复取消/释放安全；释放后的
handle 调用返回明确本地错误。

下载流程为 Queued → Running → Verifying → Publishing → Completed。运行中可进入
Pausing/Paused、RetryWaiting、Failed 或 Cancelled。进程留下的 Running 等活动状态经扫描转为待宿主确认的恢复状态；不能直接信任上次
received_bytes。

## 事件、容量与关闭

- 每任务事件有序；每个 generation 至多一个终态。进度合并到最新值，状态与终态不合并丢弃；未知总长不伪造百分比。
- 正式实现起点：控制队列 1024 条、每订阅最多 64 条待分发事件、每任务最多 64 个订阅、单次列表最多 100
  条，均参数校验并设硬上限。
- 队列满时普通命令返回 Busy，不允许无界增长。控制命令取消/关闭保留专用通道；慢订阅的非进度事件耗尽容量时终止该订阅，记录可查询的
  SubscriptionOverflow，保留一次最终通知槽，不阻塞其他订阅或核心。
- 暂停/取消可在宿主回调内调用。同步 join 不能从内部 worker 或正在执行的同一关闭回调中调用，返回
  Busy，避免自等待。
- close 先拒绝新命令、停止 I/O、尽力检查点并停止内部执行；join 只等待 SDK 自有资源静止，不等待宿主
  executor 执行积压回调。旧 generation 的已排队回调有关闭标记可丢弃。
- 活跃 lease 持有最小存储上下文和目录锁，engine 关闭后仍可读，最后一个 lease 释放才销毁上下文；同目录新
  engine 在此之前返回 Busy。close 不要求调用方先释放所有 lease，也不能使它们被淘汰。
- 上述队列、事件与共享任务机制在 M3 实现；M0 仅验证传输屏障和取消，不能宣称并发状态机已完成。

## 请求、错误与默认策略

宿主按业务引用提供短期 URL/鉴权；默认只保存引用，公共 URL 经显式允许才持久化。跨 origin
由核心清理凭证并再次询问宿主。刷新不改变资源身份，也不能跳过强校验器/可信摘要。

错误固定分为设计中的网络、超时、HTTP、鉴权、协议、完整性、磁盘、权限、配额、Busy、取消，另加
InvalidArgument、NotFound、Closed、UnsupportedMetadata、SubscriptionOverflow。错误带 HTTP
状态、平台码、是否可重试与发生阶段；不包含真实凭证或完整签名 URL。

重试起点：最多额外 3 次，1 秒指数退避并抖动，基础上限 30 秒；合法 Retry-After 可以更长，不能被本地上限缩短。鉴权刷新单轮最多
1 次；协议不匹配最多额外完整重下 1 次。证书、磁盘、权限、摘要错误不参与普通网络重试。暂停、取消和系统停止优先于重试；重试预算/下次时间可持久化并在恢复时校验。

检查点起点为 1 秒或新增 4 MiB 任一先到，暂停/发布/关闭单独触发。资源配额、未知长度上限和暂存保留期要求宿主明确设置。pin
对象过期不再命中新 acquire，现有 lease 继续有效；刷新仍走正常校验发布。

## 存储记录 v1

正式 M2 字节布局、字段编号、黄金样本及兼容策略见 [记录格式](storage-record-v1.md)。以下为 M0 的设计方向，
其中重试、pin 和时间字段由 M3 再分配；M2 不写入尚无语义的占位值。当前默认不持久化任何 URL。

受管根目录为同一文件系统内的 `tmp/`、`objects/`、`records/`
与锁文件。内部身份映射生成文件名，不信任远端路径。每任务一个独立记录，扫描逐条隔离损坏或未来版本，不能覆盖未知版本的数据。

M0 选择无序列化库的有界二进制 TLV 方向，M2 实现前固定字节格式并提供黄金样本：

- 固定魔数、格式版本、payload 长度与记录 CRC32（IEEE，使用平台 zlib 实现）；整数小端，payload 上限 64
  KiB，解析先检查长度再分配。
- TLV 字段记录 task_id、完整身份、地址业务引用/显式公共
  URL、预期长度/摘要、强校验器、committed_offset、状态、重试预算/时间、pin、访问/过期/发布时间和完整性结果。
- namespace 上限 256 字节，resource_key/representation_key 各 1024 字节，version 256 字节，业务引用
  2048 字节；其他字段设明确上限。重复必需字段、负/溢出偏移、非法状态和缺失必需字段拒绝。
- 未知可选字段可跳过；不支持的格式版本只隔离报告。CRC 只用于检测损坏，不能证明记录未被恶意篡改；SHA-256
  验证内容，具体实现和许可证评估在 M2 完成。
- 数据写入并同步后才提交 committed_offset；记录通过同目录临时文件、同步、原子替换及必要目录同步提交。同步错误不能推进偏移。
- 发布先确认传输与预期长度，再验证所需摘要，同步并记录 Publishing，同文件系统 rename，最后提交
  Completed；启动修复各中间状态。
- 启动重算配额，区分临时/最终/元数据占用；只清理可确认属于 SDK 且满足保留策略的文件。外部复制/文档 URI
  导出不使用原子发布保证。

TLV、zlib 记录校验、队列容量与错误扩展是 M0 对原设计未确定项的细化，需同步设计基线；不提前创建空的存储/缓存模块。
