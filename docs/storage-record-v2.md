# 存储记录 v2

日期：2026-10-27。M3 在 [v1](storage-record-v1.md) 封装上使用版本号 2，魔数、CRC32、整数端序、TLV 和 64
KiB payload 上限不变。 独立编码的 [v2 黄金样本](../tests/fixtures/record-v2.hex) 与原 v1 样本共同参与编解码对照。
v1 的 tag 1～16 保持语义；新增字段全部为必须理解的 8 字节无符号整数。

| tag | 字段             | 约束                                                   |
|-----|------------------|--------------------------------------------------------|
| 17  | retry_count      | 已消耗自动重试次数，0～16                              |
| 18  | next_retry_at_ms | UTC Unix 毫秒，0～INT64_MAX，0 表示无等待              |
| 19  | auth_refreshes   | 当前 generation 的鉴权刷新次数，0 或 1                 |
| 20  | updated_at_ms    | 最近实际任务/策略提交时间，用于暂存保留期；扫描不刷新  |
| 21  | access_order     | 持久化 LRU 序号，不能为 UINT64_MAX；启动取最大值后继续 |
| 22  | expires_at_ms    | UTC Unix 毫秒，0 为不设置到期时间                      |
| 23  | pinned           | 0 或 1                                                 |

v2 必须包含 tag 1～14 和 17～23；15/16 仍可省略以区分未知长度和已知空文件。 状态扩展：10 为
RetryWaiting，11 为 Removed。Removed 是删除事务 tombstone，重开完成清理后移除记录。 记录不编码
URL、headers、provider、订阅 token、事件队列、进程内 lease 或空间预留。

M3 读取 v1 时保留身份、前缀、长度、ETag、generation 和完整性，新增策略取默认值，写回 v2；未知年龄以首次迁移时间开始计。
M2 只理解版本 1，会拒绝/隔离版本 2；不能把新字段写成旧版本可静默忽略的可选字段，否则旧实现可能丢失
pin/重试语义。 v1 中出现 tag 17～23 也按不支持的元数据处理，避免重写时丢字段。
未来版本和未知必须字段继续逐条隔离、保留原字节并保护身份；不以重新入队覆盖。

容量账本按当前文件逻辑长度重算。每个有效记录保留两份最大记录的元数据预算（2×65556）， 尚未使用的数据预留、活动任务保护和
lease 计数都是进程内状态；恢复时必须重新申请，不能把它们当成持久化事实。
租约、删除和活动任务保护共用短时保护锁；磁盘/记录操作串行化，不在宿主回调期间持锁。
