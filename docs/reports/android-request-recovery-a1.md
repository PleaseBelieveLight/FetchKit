## 原因与修复

| 问题原因                                       | 修复行为                                                                |
|------------------------------------------------|-------------------------------------------------------------------------|
| 鉴权失败不满足 resume/重新 enqueue 的执行条件  | 增加原子 retry(request)，允许失败后重新许可执行，保留合法检查点         |
| 共享任务总选最早订阅，追加新地址不能替换旧来源 | 显式 retry 的调用订阅成为首选来源，取消/释放后按屏障交接                |
| provider 的暂时断网也映射为 AuthRequired       | Kotlin 类型化异常和 C ABI 保留受限 Network/Timeout 等分类，参与有限重试 |
| 某些链接用 404/410 表示失效                    | 增加有界的显式刷新选项，默认行为保持；所有刷新状态共用一次额度          |

新接口横跨 C/C++、JNI 和 Kotlin，原请求结构、错误/状态编码及记录 v2 格式未改变。
普通重试次数与 Retry-After 不清零，身份/完整性约束不覆盖；可用性仍由 acquire/校验决定。
sample 增加更新地址重试入口，已知请求保留原长度/摘要；进度流继续使用同一订阅。

## 环境异常与资源管理

初始仅约 2.5 GiB 可用内存，先以单线程运行 native；内存回升至约 5.4 GiB 后才执行 Gradle 和 1 GiB AVD。
构建、模拟器及主机协议检查顺序运行。只关闭本次启动且已完成测试的模拟器，未结束其他任务进程。

首次受限环境的服务器测试因 WinError 10013 无法连接回环端口；在允许回环的环境重新执行并通过最终 6/6
检查。
追加 sample 控制测试的首次系统就绪检查失败，尚未进入 instrumentation；保留失败 JSON。
重开同一现有 AVD 后，核心包/系统服务检查正常，原来的连续 30 秒稳定门槛通过，随后 1 个控制用例通过。
未改动就绪检查器或降低断言；两次就绪结果均记录在摘要中。

## 保证范围

未执行 Linux/ASan/UBSan/TSan、物理 arm64、API 24/目标 API 矩阵、实际 Android >4 GiB、物理重启或掉电。
本轮未做新的 native 安装/外部消费者、Release/R8 宿主和完整依赖/体积测量；这些仍属于后续 A5/发布门槛。
没有上传产物，不声明稳定 ABI；新增 Kotlin 参数需要随 SDK 重新编译宿主。
