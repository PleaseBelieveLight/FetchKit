# M0 基线与关键假设报告

日期：2026-10-26。基线为 `770afae` 后的 M0 工作区实现；[体积证据](m0/size-arm64.json) 同时记录关键源码与构建脚本的
SHA-256，避免把未提交实现误归于基线提交。

结论：M0 工程化产物已落地，当前 Windows 主机和 API 31 模拟器上的实验完成； **Linux、真机及其他 API 缺测，M0
不能标为全部通过**。原 HttpURLConnection 候选不符合凭证隔离契约；独立配置的 OkHttp 对照通过已覆盖场景，作为正式
Android 后端的实现方向。没有实现或发布下载、续传、检查点和缓存 API。

## 3. 取消测量

每类 100 次。时间从 cancel 被接受前的计时点开始，直到网络 worker 与取消清理线程均退出；重复调用 cancel
验证幂等。头屏障与背压采用 latch/条件变量命中，阻塞读取在首块交付后等待 30 ms 再取消。关闭竞态允许在
I/O 尚未开始时命中，不当作已经进入阻塞读取。

| 情形          | libcurl/Windows p95 / max（ms） | HttpURLConnection/API31 p95 / max（ms） | OkHttp/API31 p95 / max（ms） |
|---------------|---------------------------------|-----------------------------------------|------------------------------|
| 等待响应头    | 45.930 / 48.380                 | 2.883 / 5.023                           | 3.050 / 4.191                |
| 阻塞读取      | 32.315 / 32.780                 | 2.694 / 3.545                           | 3.176 / 5.186                |
| 等待头接受    | 0.668 / 1.326                   | 2.050 / 3.201                           | 7.705 / 9.583                |
| 背压等待      | 0.685 / 0.795                   | 1.974 / 3.607                           | 3.443 / 12.463               |
| 启动/关闭竞态 | 0.076 / 0.658                   | 1.958 / 2.159                           | 2.070 / 2.255                |

三者在此环境均满足实验目标 p95 ≤ 1 秒、单次 ≤ 3 秒。平台方案的整体 gate 仍因凭证策略失败而失败。没有检查点实现，因此这里不包含
Paused 数据同步时间；也不是外网 DNS/TLS、真机或所有 Android API 的取消保证。

摘要和每次原始样本分别保存：

- [libcurl 摘要](m0/curl-windows.json)、[508 条样本](m0/curl-windows.samples.jsonl)。
- [平台方案摘要](m0/android-platform-api31.json)、[508 条样本](m0/android-platform-api31.samples.jsonl)。
- [隔离方案摘要](m0/android-okhttp-api31.json)、[508 条样本](m0/android-okhttp-api31.samples.jsonl)。

## 4. 编码、响应与凭证结论

| 检查                                              | 主机 libcurl          | Android 平台                        | Android 独立客户端        |
|---------------------------------------------------|-----------------------|-------------------------------------|---------------------------|
| 固定内容、Range 206 与 JNI/主机指纹一致           | 通过                  | 通过                                | 通过                      |
| 重复响应头不丢失                                  | 通过                  | 通过                                | 通过                      |
| 头拒绝后无 body 交付                              | 通过                  | 通过                                | 通过                      |
| identity 请求；服务端强制 gzip 时拒绝、不透明解码 | 通过                  | 通过                                | 通过                      |
| 302 保留给核心，不自动跳转                        | 通过                  | 通过                                | 通过                      |
| 截断与读空闲超时不误报正常完成                    | 通过                  | 通过                                | 通过                      |
| 宿主全局 Cookie 不隐式发送                        | 不使用 JVM 全局处理器 | **失败，已发送**                    | 通过，未发送              |
| 401 不触发宿主全局 Authenticator                  | 不使用 JVM 全局处理器 | **失败，调用 1 次并自动请求至 200** | 通过，调用 0 次，保留 401 |

问题原因：`HttpURLConnection` 会读取进程全局 CookieHandler，并在认证挑战时使用全局 Authenticator；关闭
instanceFollowRedirects/useCaches 和声明 identity 不能隔离这些策略。这会使 C++ 核心失去对凭证发送和鉴权重试的控制。

处理方式：保留平台探针作为可复现反例，排除它作为默认实现；增加独立配置的 OkHttp 5.5.1 对照，显式设置
NO_COOKIES、Authenticator.NONE、proxyAuthenticator.NONE、禁用自动连接重试/重定向/缓存。禁止修改宿主全局处理器来“修复”测试。设计基线已同步，正式后端仍须完成
M1/M4 的完整协议、TLS、连接和生命周期验证。

## 5. 体积与依赖

统一口径：同一最小 Java Activity、arm64-v8a、Release、R8 关闭、unsigned APK、同一资源/包名/构建工具。空宿主关闭内建
Kotlin，SDK 需要的 Kotlin 标准库不会提前算入空宿主。APK 中 native 库以未压缩条目交付，AAR 为 ZIP
压缩；对齐填充使 APK 差值不等于各文件差值之和。

| 配置                    | APK（字节） | 相对空宿主增量（字节） | arm64 JNI strip 后（字节） | 单 ABI AAR（字节） |
|-------------------------|-------------|------------------------|----------------------------|--------------------|
| bare                    | 2,420       | 0                      | 无                         | 无                 |
| scaffold                | 862,376     | 859,956                | 208,736                    | 70,919             |
| HttpURLConnection probe | 863,392     | 860,972                | 209,752                    | 85,244             |
| 独立 OkHttp probe       | 1,402,540   | 1,400,120              | 209,752                    | 86,322             |

独立客户端实验比平台探针多 539,148 字节 APK 增量（约 527 KiB），包含 OkHttp、Okio、Kotlin
标准库版本提升、AndroidX annotation/startup/tracing 等实际解析依赖，不能仅用 86,322 字节 AAR
表示接入成本。SDK AAR 不嵌入传递依赖。

普通 SDK 双 ABI AAR 为 **140,418 字节**，含 arm64 JNI 208,736 字节与 x86_64 JNI 208,152 字节；两者均使用
`c++_static`，成本已进入 JNI。当前仅版本函数的核心静态归档为 3,170 字节，含调试信息；它不是可与最终 JNI
等价的 strip 后核心指标。最终核心独立测量目标在功能实现后补齐。

[体积明细与产物/源码哈希](m0/size-arm64.json) 包含 native 编译配置和导出检查，各实验 JNI 的全局函数导出均仅为
JNI_OnLoad。APK/AAR 二进制和完整构建日志保留在 `build/m0-size/`，不提交 Git。

依赖证据：普通 SDK 的 [依赖树](m0/dependencies-scaffold.txt)
、候选实验的 [完整依赖树](m0/dependencies-okhttp.txt)、[已解析组件及本地制品哈希](m0/dependencies.json)
。普通 SDK 仍只有原有 Kotlin 依赖；OkHttp/Okio 仅在显式开启对应实验时加入。基线 Kotlin stdlib 为
2.2.10，候选实验解析为 2.2.21，未改变 Kotlin 插件版本。

依赖清单记录已取得的 POM 许可和制品校验值；元数据重定向模块没有独立运行时制品。它不是强制 dependency
lock 或最终许可证审计。Linux 参考构建的可复现依赖获取/锁定与发布许可证清单仍需补齐；不能声称系统安装包已被项目锁定。

M0 阶段回归预算从实测建立：普通双 ABI AAR ≤ 160 KiB、普通 arm64 JNI ≤ 224 KiB、候选实验 APK 接入增量 ≤
1.5 MiB、取消 p95 ≤ 1 秒/最大 ≤ 3 秒。它们仅用于这批 M0 功能的回归；M1/M2
增加真实核心能力时须先说明新增代码/依赖，再更新预算，不能当作首版最终体积承诺。

## 7. 进入 M1 前的剩余门槛

1. 提供 Linux 环境，安装或构建明确版本的 libcurl 开发依赖，在干净环境执行同一 CTest 与取消矩阵；将
   resolver、TLS 库、来源、版本和哈希纳入锁定策略。本机没有发行版或容器运行时，未安装/替换操作系统。
2. 在目标 arm64 真机，以及 API24 边界/目标 API 组合补测关键假设，尤其解析、连接/TLS 取消和宿主网络配置差异。当前不把
   x86_64 模拟器结果推广为真机保证。
3. 接受以已测独立客户端为 Android 实现方向，继续核查 408/503、重定向和鉴权等后端自动行为。M0 场景只覆盖
   302/401 和基本读取，不能代替 M1 全协议矩阵。
4. 正式队列、generation、C ABI、检查点、CRC/摘要、配额及租约依次进入后续里程碑；当前仅同步背压实验，尚未验证双缓冲队列和进程恢复。
5. R8 优化后接入体积、设备安装占用、完整核心独立尺寸、性能/线程/内存长稳和更强存储保证另行测量，不从当前
   APK/AAR 推导。

M0 产物可直接复用到后续开发；当前报告保留缺测和拒绝的假设，不提前宣布整个阶段验收完成。
